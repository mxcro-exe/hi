MISSION
Build a mobile-first React + Vite + Tailwind app where a patient (or family member,
often non-technical, possibly elderly) uploads a medical document, VERIFIES what the AI
extracted, understands results in plain language (English + Tamil), and sees a clear
health timeline. This carries UX 20% + Demo 10% and is the first thing judges see.

WORKFLOW: PLAN FIRST
Inspect the repo, then output a plan: screens, routes, components, state approach,
design system (colors, typography, spacing), i18n strategy, mock strategy, accessibility
and test plan. STOP for approval. Use a calm, trustworthy healthcare look (not a generic
template): clear hierarchy, large readable type, generous touch targets.

API LAYER (strict)
All network access lives in src/api.js only. VITE_USE_MOCK=true -> load contract/mock_*.json
(copy or import them), simulate 1.5 s latency and occasionally a configurable error to test
states. VITE_USE_MOCK=false -> call VITE_API_URL exactly per the API CONTRACT. No direct fetch
in components. No API keys in frontend, ever. Treat missing/null fields defensively
(optional chaining, fallbacks), the contract allows null and [].

SCREENS (build in this order; smallest working slice first)
P1 (core)
1. App shell: header, profile switcher (default profile), bottom nav on mobile
   (Upload, Timeline, Medicines, Settings/Language).
2. Upload: camera capture + file picker + drag-drop, file type/size hints, progress and an
   "Analysing your report..." state with friendly steps (reading, extracting, checking values).
3. VERIFY screen (most important differentiator): on desktop, original document on the left
   (GET /records/{id}/file) and extracted fields on the right; on mobile, tabs or stacked.
   Fields with confidence < 0.7 or listed in needs_review are highlighted yellow with a
   "Please check" label (icon + text). Every value editable. Highlight the bbox region on the
   image when bbox exists. "Confirm & save" sends PUT with the corrected record. Never
   present unverified data as confirmed.
4. Summary: summary_en/summary_ta, per-test cards with LOW (blue, down arrow), HIGH (red,
   up arrow), NORMAL (green, check), UNKNOWN (grey). Color is never the only signal.
   Show explanation_en. The fixed disclaimer is ALWAYS visible (sticky/footer, not dismissible).
   Add an "AI-generated, please confirm with your doctor" label near summaries.
5. Timeline: date-descending cards from /timeline (doc type icon, headline, abnormal
   count, medicines), tap to open the record. Draft vs confirmed badge.
6. Every screen implements 4 states: loading (skeleton), empty (helpful call to action),
   error (friendly message from error.message + Retry), success.
P2
7. Trend charts (recharts) from /trends with reference band and flag-colored points; test selector.
8. Language toggle English/Tamil: UI strings via i18n JSON files (complete Tamil strings for
   all UI); summary uses summary_ta when selected, falls back to English with a note if null.
9. Read-aloud via Web Speech API: use a ta-IN voice if available; if not, show a friendly
   message and fall back to English. Provide stop control.
10. Daily medicine schedule: Morning / Afternoon / Night grid from schedule_parsed with
   food instruction (before/after food).
11. Duplicate-medicine alert banner from /alerts (neutral wording, "ask your doctor or pharmacist").
12. ABHA screen: link and import mock endpoints, a persistent "MOCK / DEMO" badge, no claim
    of real government integration.
P3 (stretch)
13. Emergency card (conditions, current medicines, allergies if present) with QR, printable.
14. Doctor-visit summary export (print-to-PDF page).
15. "Ask my records" chat (only when /ask exists; show sources; show "not found" responses properly).

ACCESSIBILITY & RESPONSIVENESS
Test at 375px, 768px, desktop. Semantic HTML, labels on inputs, visible focus, keyboard
navigation, WCAG-level contrast, minimum 44px touch targets, aria-live for loading/errors,
reduced-motion support. Font size at least 16px for body text.

SAFETY UX

you verified" distinction visible (draft vs confirmed). Delete-my-data option in Settings
calling DELETE with a confirmation dialog.
