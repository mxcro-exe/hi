# AI Health Copilot: Shared Project Context (FROZEN)

## Product
Hackathon project (Altrix Labs challenge: AI-Powered Personal Health Copilot).
Flow: user uploads a medical document (prescription / lab report / discharge summary)
-> AI extracts structured data -> user VERIFIES extracted values -> plain-language
summary with abnormal-value explanation -> unified health timeline.
Bonus: Tamil support, ABDM/ABHA-ready (FHIR-style data + MOCK ABHA link).

## Judging rubric (build priorities)
AI Utilization 35% (extraction accuracy, summary quality, abnormal-value explanation)
Technical Architecture 25% (clean pipeline, storage, structured model, ABDM/FHIR schema)
User Experience 20% (easy upload, readable summaries, clear timeline)
Healthcare Impact 10% (medical correctness, safe wording, disclaimers, no misleading claims)
Presentation & Demo 10% (working prototype)

## Absolute rules (all 3 people)
1. Core flow first (upload -> extract -> verify -> summary -> timeline). Extras only after it works end to end.
2. NEVER diagnose, prescribe, suggest treatment, or claim drug interactions. Safe wording + disclaimer always.
3. Abnormal flags come from CODE (reference ranges), never from the LLM.
4. Never fabricate data, accuracy numbers, test results, or integrations. Mock features must be labeled MOCK/DEMO.
5. No real patient data. Synthetic samples only.
6. Secrets only in .env (never committed, never in frontend code, never in logs).
7. Do not edit folders owned by other people. Do not change the contract or API silently.
8. Never claim something is tested unless it was actually run.

## API CONTRACT (Backend implements, Frontend consumes). Base: http://localhost:8000/api
POST   /profiles/{pid}/records        multipart "file" -> 200 {"record_id","status":"draft","record":<contract>}
GET    /records/{id}                  -> {"record_id","status","record"}
GET    /records/{id}/file             -> original image/pdf bytes
PUT    /records/{id}                  body {"record":<contract>} -> status "confirmed"
GET    /profiles/{pid}/timeline       -> {"items":[{"record_id","doc_type","doc_date","status","headline","medicines":[...],"tests":[...]}]} sorted by date desc
GET    /profiles/{pid}/trends?test=HbA1c -> {"test","unit","points":[{"date","value","flag","record_id"}]}
GET    /profiles/{pid}/alerts         -> {"alerts":[{"type":"duplicate_generic","generic","medicines":[...],"record_ids":[...],"message"}]}
GET    /records/{id}/fhir             -> FHIR R4 Bundle JSON
POST   /profiles/{pid}/abha/link      body {"abha_id"} -> {"mock":true,"status":"linked",...}   MOCK
POST   /profiles/{pid}/abha/import    -> {"mock":true,"imported_record_ids":[...]}              MOCK
DELETE /profiles/{pid}                -> {"deleted":true}
POST   /profiles/{pid}/ask            body {"question"} -> {"answer","sources":[{"record_id","field"}],"grounded":true}  (stretch)
GET    /health                        -> {"status":"ok"}
Default profile id for demo: "default". Errors always: {"error":{"code":"...","message":"user-friendly"}}

## AI engine <-> backend interface (Python import, no network)
from ai_engine import extract_record
extract_record(file_path: str, mime: str, lang_hint: str = "auto") -> dict   # returns contract dict, NEVER raises
Backend adds repo root to sys.path. Backend env USE_MOCK_AI=true returns contract/mock_*.json by doc type.

## Run
backend:  cd backend && pip install -r requirements.txt && uvicorn app.main:app --reload --port 8000
frontend: cd frontend && npm install && npm run dev   (http://localhost:5173)
ai cli:   python -m ai_engine.cli samples/<file>
